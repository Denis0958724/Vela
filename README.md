# Vela

Десктопний агент-програміст для Windows, що працює напряму з API-ключами
провайдерів. Окреме вікно: проєкти з чатами, робота з файлами, запуск команд,
створення сайтів і вбудований перегляд результату.

## Дизайн

Одна ідея: глибокий індиго-робочий стіл, у якому чат це головна поверхня, а панелі
лише обрамлення. Один лавандовий сигнальний колір тримає дію, активний стан і роботу
агента. Кути заокруглені, але не до стану «сторінка з картками».

- Заголовки й текст працюють на контрасті, технічні підписи набрані
  моноширинним. Ієрархія тримається на розмірі й відступах, а не на рамках.
- Базова тема **Індиго**: глибокий фіолетовий графіт і лавандовий акцент.
  **Світла** це білий папір з оксидним оранжевим, **Ніч** це чорний графіт із м'ятним акцентом.
- Немає декоративних градієнтів, скляних шарів і сторонніх ілюстрацій. Лінія
  навколо поля вводу рухається лише тоді, коли агент справді працює.
- Основний текст чату 14.5 px із міжрядковим 1.72, інтерфейс 14 px. Це ближче
  до Antigravity і читається без нахилу до монітора.
- На вузькому вікні права панель стає накладкою. Чат не стискається до
  п'яти слів у рядку.

## Запуск

```bash
npm start
```

Для розробки з автоперезбіркою:

```bash
npm run dev
```

## Підключення

Прямі ключі додаються у **Налаштування → Провайдери**. Вони шифруються системним
сховищем Windows. Окремого шлюзу FreeLLMAPI більше немає.

## Робоча папка й проєкти

Агента можна використовувати без проєкту: вгорі лівої панелі є секція **Робоча
папка**, яка при першому запуску вказує на домашню теку. Кнопкою поруч її можна
змінити на будь-яку іншу — агент одразу працює там, із власними чатами.

У звичайному чаті без проєкту біля скріпки є кнопка **Додати папку**. Вона
прив'язує до цього чату окрему теку, не змінюючи інші чати. Якщо папку не
вибрано, чат працює у спільній робочій папці зліва.

Проєкт — те саме, але названо й збережено окремо: папка, в якій працює агент.
У проєкті кнопки **Додати папку** немає: агент завжди працює лише в папці
проєкту. У кожному проєкті може бути **до 5 чатів**; у кожного чату власна
історія, яка зберігається на диск після кожного ходу, тож закриття вікна її не
втрачає.

- `+` — новий проєкт (теку буде створено в папці з параметрів).
- Іконка теки — підключити **наявну** папку як проєкт.
- Правий клік на проєкті: відкрити папку, перейменувати, прибрати зі списку.
  Прибирання видаляє проєкт лише з Vela — папка на диску лишається.

Назва чату підставляється з першого повідомлення.

## Якщо папку проєкту переміщено

Vela не вважає шлях до папки вічним. Він перевіряє його під час запуску, після
повернення у вікно, раз на 30 секунд і перед кожним ходом — і в кожній ситуації
поводиться передбачувано:

| Ситуація | Що робить Vela |
| --- | --- |
| Папку перейменували або перенесли, застосунок був закритий | Проєкт у списку позначено «немає папки», у чаті — банер із кнопками **Вказати папку**, **Знайти**, **Прибрати**. Чати й історія не зникають. |
| Папку перенесли, застосунок відкритий | Банер з'являється після повернення у вікно або протягом пів хвилини. Надсилання повідомлення теж одразу показує стан папки. |
| Папку перенесли **під час ходу** | Перший інструмент, якому потрібна папка, отримує зрозумілу помилку; хід зупиняється, у чаті з'являється картка «Папку проєкту втрачено» з кнопками відновлення. Агент не сипле ENOENT до ліміту кроків. |
| У черзі вже є повідомлення, а папка зникла | Черга не запускається наосліп: показує «Спочатку вкажи актуальну папку», а повідомлення лишається в черзі. Після відновлення шляху — кнопка **Надіслати**. |
| Папку перейменували | **Знайти** переглядає стару теку, теку проєктів, домашню, Desktop, Documents і Downloads. Кандидати зі схожою назвою (`proj`, `proj-old`, `proj 2`) показуються списком; якщо нічого не знайдено — відкривається звичайний вибір теки. |
| Папка є, але недоступна (права, мережевий диск) | Банер каже «папка існує, але недоступна» — це не те саме, що «не знайдено». Хід не почнеться. |
| За старим шляхом лежить файл | Окреме повідомлення «це файл, а не папка»; агент не намагається працювати з ним. |
| Треба змінити папку, поки агент працює | Дію заблоковано: спершу завершити або зупинити хід, щоб частина роботи не пішла в стару теку. |
| Зникла тека звичайних чатів | Такий самий банер із кнопкою **Вибрати теку**; історія чатів залишається. |

«Прибрати» прибирає проєкт лише зі списку Vela — папка на диску
залишається. «Вказати папку» змінює шлях, не чіпаючи ні чати, ні файли.

## Розкладка

| Зона | Вміст |
| --- | --- |
| Ліва панель | проєкти та їхні чати, тека звичайних чатів, **Налаштування** |
| Центр | шапка чату з текою, повідомлення, картки інструментів, запити дозволу, черга, вибір моделі, індикатор контексту й поле вводу |
| Права панель | вкладки **Файли**, **Редактор**, **Прев'ю** |

Межі між панелями перетягуються мишею; подвійний клік по межі повертає типову
ширину. Обидві бічні панелі згортаються — кнопками у верхній панелі або
`Ctrl+B` (ліва) та `Ctrl+\` (права). Ширини й згорнутий стан зберігаються між
запусками.

## Як видно, що агент працює

Поки триває хід, під останнім повідомленням пульсують три крапки, а по всьому
контуру поля вводу безперервно біжить лінія — вона заокруглюється разом із полем
і не ріже кнопки всередині. Картки викликаних інструментів **не накопичуються в
чаті**: видно лише те, що виконується зараз, а завершені згортаються в один
рядок («7 дій виконано»), який розгортається кліком. Виклик, що завершився
помилкою, лишається розгорнутим на видноті.

## Вигляд чату

- Відповіді агента читаються як звичайний текст без рамки; повідомлення
  користувача — окремий бульбашка праворуч.
- Під кожною відповіддю є час, **копіювати** (сирий Markdown), а в агента —
  ще й **корисно / не те**. Оцінка зберігається локально в застосунку.
- У блоках коду є кнопка копіювання; інлайн-код, схожий на шлях до файлу
  проєкту (`src/app.js`), відкривається в редакторі кліком.
- Порожній чат пропонує три стартові підказки; коли список довгий, з'являється
  кнопка повернення вниз, а якщо ви читаєте вище — нові токени не смикають
  екран.
- У шапці чату видно назву й теку; тека клікабельна.
- Унизу, біля поля вводу, — вибір моделі з її лімітом контексту та кільце
  використання контексту. Клік по кільцю показує розподіл: системний промт,
  опис інструментів і повідомлення.

## Налаштування

Кнопка з шестернею у верхній панелі, **Налаштування** внизу лівої панелі або
кнопка підключення відкривають один діалог із бічною навігацією:

- **Загальні** — тека для нових проєктів, глобальні інструкції, скидання ширини
  панелей;
- **Вигляд** — теми **Індиго**, **Папір** і **Ніч**;
- **Дозволи** — інтернет, файли й керування комп'ютером;
- **Провайдери** — прямі ключі Google AI Studio, Groq, NVIDIA NIM, OpenRouter і OrcaRouter;
- **Моделі** — поточний каталог, ліміти й перевірка моделей;
- **Розширення** — каталог застосунків, MCP-інструменти й інструкції;

### Вигляд

Одна система для всіх трьох тем: графітовий дек, папір і чистий чорний.
Спільні правила — один сигнальний колір (крижаний у темних темах, глибокий
бірюзовий у світлій), волосяні розділювачі замість тіней, моноширинні
мікропідписи, радіуси 5–12px. Вікно без нативної рамки: верхня панель сама
виконує роль заголовка, тому системний акцент Windows не фарбує смугу зверху.

Рух — лише на зміну стану: 120ms, `cubic-bezier(.22,.75,.24,1)`, тільки
`opacity`, `transform`, колір і рамка. Анімація розкладки й `transition: all`
заборонені; `prefers-reduced-motion` вимикає все.

Перевірити це можна двома командами:

```
npm run design:audit   # контраст, токени, дорогі анімації, залишки старих палітр
npm run preview        # 8 PNG у screenshots/preview: чат і налаштування в трьох темах
```

`preview` запускає справжній рендерер у прихованому вікні Electron, тому
дизайн можна переглянути, не чіпаючи робочий стіл і не витрачаючи токени.

## Прямі провайдери

У **Налаштування → Провайдери** можна додати ключі Google AI Studio, Groq,
NVIDIA NIM, OpenRouter і OrcaRouter. Ключі шифруються системним сховищем
Windows, у `providers.json` лежить лише шифр.

Моделі прямих провайдерів з'являються у вкладці **Моделі** з назвою провайдера.
Їх можна вимкнути, перевірити або вибрати для чату. Стратегія маршрутизації
визначає порядок запасних моделей: збалансована, найрозумніша або найшвидша.
Використання токенів рахується локально за місяць; якщо провайдер не повертає
usage, Vela показує власну оцінку.

FreeLLMAPI більше не використовується. Якщо прямий провайдер падає до першого
токена, запит пробує іншу модель того самого провайдера.

Розширення більше не висять окремими кнопками в лівій панелі: вони
всередині налаштувань. Кожна вкладка зберігає свої зміни окремо, тому
перемикання вкладок не скасовує введене.

На вузькому вікні права панель не стискає чат до кількох слів: вона
автоматично згортається, а та сама кнопка відкриває її поверх чату.

## Вкладення

До повідомлення можна додати зображення, відео або текстовий файл — скріпкою,
перетягуванням у поле вводу або просто `Ctrl+V` зі скріншотом у буфері.

- Зображення стискаються до 1280px і йдуть як JPEG — повноекранний скріншот
  важить близько 50 КБ замість кількох мегабайтів.
- **Відео розкладається на 8 кадрів**, рівномірно по всій тривалості, через
  ffmpeg. Жодна з доступних моделей відео не читає, тож без цього кроку сенсу
  не було б. Якщо ffmpeg не знайдено — про це скажуть, а не проковтнуть.
- Текстові файли вкладаються в промт; двійкові чемно відхиляються.

Більшість моделей із tools **зору не мають**. Якщо до повідомлення додано
зображення, хід автоматично перемикається на модель, яка його бачить, і в чаті
з'являється рядок на кшталт `gpt-oss-120b не читає зображення — беру
gemini-3.1-flash-lite`.

## Посилання, файли й зображення

- Markdown-посилання й голі URL у відповіді відкриваються в браузері.
- `[назва](src/app.ts:24)` відкриває файл у редакторі на вказаному рядку.
- Інлайн-код із шляхом теж стає переходом у редактор.
- `![опис](шлях.png)` показує локальне зображення прямо в чаті.
- Клік по зображенню відкриває перегляд на весь екран зі стрілками й лічильником.
- Інструмент `show_image` дозволяє агенту показати картинку з робочої папки.
- Скріншот із `computer` автоматично з'являється в чаті як зображення.

Локальні картинки читаються лише з робочої папки, лише PNG, JPG, WebP або GIF,
з обмеженням 16 МБ.

## Черга повідомлень

Поки агент працює, поле вводу лишається активним, а кнопка надсилання не зникає —
вона перетворюється на **У чергу**. Enter і кнопка роблять те саме: повідомлення
не перериває поточний хід і не губиться, а стає в чергу й іде одразу після
завершення. Вкладення теж їдуть разом із повідомленням, а не лишаються в полі.

- Черга **окрема для кожного чату**: перемикання між чатами не перемішує
  повідомлення й не втрачає їх.
- Клік по елементу черги повертає його в поле разом із вкладеннями, щоб
  виправити перед відправкою; хрестик прибирає його зовсім.
- **Стоп** зупиняє поточний хід і не запускає чергу наосліп: повідомлення
  лишаються видимими, і їх можна надіслати кнопкою **Надіслати**.
- Якщо папка проєкту зникла, черга не виконується, доки шлях не відновлено —
  текст при цьому не втрачається.
- Черга живе в межах сесії; після повного перезапуску застосунку вона не
  відновлюється (історія чатів — так).

## Інструкції

Постійні інструкції більше не висять кнопкою в шапці чату:

- **Загальні** редагуються в **Налаштування → Загальні**;
- **Проєкту** — через праву кнопку на проєкті → **Промт проєкту**.

Їх можна змінювати будь-коли, зокрема **під час роботи агента**. Поточний хід не
переривається: нові інструкції додаються до системного промту з наступного
повідомлення — і для повідомлень, що вже стоять у черзі. Зміни зберігаються на
диск одразу, перезапуск не потрібен.

## Прогрес не губиться

Історія пишеться на диск **після кожного кроку**, а не в кінці ходу: закриття
вікна чи втрата живлення посеред роботи зберігають усе, що агент уже зробив.
Якщо застосунок закрився під час відповіді, при наступному запуску в чаті
з'являється позначка про перерваний хід і кнопка повтору.

Кнопка **Повторити** під останньою відповіддю прибирає стару відповідь і
запускає той самий запит заново, не додаючи другу бульбашку користувача.

Якщо зник інтернет, застосунок не перебирає всі моделі навмання: показує
зрозумілу помилку, зберігає часткову відповідь і не запускає чергу до
наступної спроби. Черга зберігається між запусками.

## Редактор

Клік по файлу в дереві відкриває його у вкладці «Редактор»:

- підсвітка синтаксису для HTML, CSS, JS/TS, JSON і Markdown — власний
  легкий токенізатор, без зовнішніх бібліотек (CSP забороняє віддалені скрипти);
- нумерація рядків, `Tab` ставить відступ, крапка біля імені файлу показує
  незбережені зміни;
- `Ctrl+S` — зберегти, `Ctrl+P` — швидкий пошук файлу за назвою.

## Розширення

Розширення-інструкція — набір інструкцій під тип задач, звичайний `.md` з frontmatter:

```markdown
---
name: static-site
description: Структура й вимоги до статичного сайту
always: false
---

# Статичний сайт
…
```

Агент бачить лише назви й описи, а тіло підтягує сам інструментом `use_skill`,
коли плагін доречний — тому десяток плагінів не роздуває кожен запит. Прапорець
«завжди» вмикає плагін у системний промпт для всіх запитів.

Діалог плагінів дозволяє створювати, редагувати, видаляти та імпортувати `.md`.
Відкривається в **Налаштування → Розширення → Інструкції**. Файли лежать у
`%APPDATA%\Vela\skills\` — їх можна тримати в git.

Плагін можна встановити з GitHub: встав посилання на репозиторій, теку з
`SKILL.md` або сирий `.md`. Vela сама спробує `SKILL.md`, потім `README.md`.

У комплекті три приклади: `static-site`, `code-review` і `writing-style`.

### Інструменти

Розширення-інструмент — це **MCP-сервер**, через який агент дістає зовнішні
інструменти. Реалізовано сам протокол, тож працює будь-який наявний MCP-сервер
(GitHub, Postgres, Notion, файлові) — окрема інтеграція під кожен не потрібна.
Редактор — у **Налаштування → Розширення → Встановлені**.

Два транспорти: `stdio` (локальний процес — команда, аргументи, змінні
середовища) і `http` (адреса та заголовки).

Як це влаштовано:

- Ключі лежать у `%APPDATA%\Vela\connectors.json` і **в запит до моделі не
  потрапляють** — модель бачить лише назву й опис, як з плагінами. У діалозі
  збережений секрет показується тільки як назва ключа; порожнє поле означає
  «не чіпати», а не «стерти».
- Інструменти конектора отримують префікс `mcp__<назва>__<інструмент>`.
- **Кожен зовнішній виклик питає дозволу окремо** — це єдине місце, звідки дані
  можуть піти за межі машини.
- Діє в усіх проєктах або лише в активному — на вибір.

## Режими дозволів

Режим вибирається кнопкою **Режим** у верхній панелі. До кожного пункту є коротке пояснення.

| Режим | Поведінка |
| --- | --- |
| `звичайний` | питає перед змінами, командами й інтернет-викликами; керування ПК автономне |
| `авто` | сам змінює файли, але питає за команди, видалення й конектори |
| `турбо` | не питає нічого, команди й видалення виконуються одразу |

Інтернет, файли й керування комп'ютером додатково вмикаються в
**Налаштування → Дозволи**. Режим не обходить ці перемикачі: якщо дозвіл
вимкнений, відповідні інструменти просто не показуються моделі.

## Інструменти агента

`read_file`, `write_file`, `edit_file`, `list_dir`, `search_files`, `make_dir`,
`delete_path`, `run_shell`, `open_url`, `web_fetch`, `web_search`, `computer`,
`use_skill`.

`run_shell` виконує команди в PowerShell у корені проєкту. Запис, редагування,
видалення й `run_shell` належать до **керування файлами**; інтернет-інструменти
й `computer` мають окремі дозволи. У `авто` файли змінюються без питання, а
команди, видалення й конектори ще питають. У `турбо` не питає нічого.
Керування комп'ютером працює автономно після явного дозволу.

## Інтернет, файли й керування комп'ютером

У **Налаштування → Дозволи** є три перемикачі.

- **Інтернет** дає агенту `open_url` (відкрити сторінку в типовому браузері),
  `web_fetch` (прочитати текст сторінки) і `web_search` (знайти сторінки).
- **Керування файлами** дає запис, редагування, видалення й `run_shell`.
- **Керування комп'ютером** дає `computer`: відкрити програму, показати вікна,
  перемкнути фокус, зробити знімок екрана, рухати курсор, клікнути або
  двічі клікнути, ввести текст, натиснути клавіші чи прокрутити.

Керування комп'ютером не питає підтвердження для кожної дії: дозвіл дається
самим перемикачем. Поки Vela діє, краї екрана світяться кольором поточної теми,
а в чаті видно напис **Вела користується вашим ПК**. Це не пісочниця для ОС:
`run_shell` і файлові інструменти працюють у вибраній папці.

Дії з вікнами й клавіатурою підкоряються двом правилам, без яких агент виглядав
би сліпим:

- **Фокус.** `open_app` сама виводить вікно програми вперед і перевіряє, що воно
  справді активне. Якщо програма вже відкрита, `focus` перемикає на неї за
  частиною заголовка або назвою процесу. `type` і `key` відмовляються працювати,
  коли у фокусі сама Vela, замість того щоб тихо вводити текст у поле чату.
- **Координати.** У відповіді `screenshot` вказано розмір екрана й позицію
  курсора, а `click` поза цими межами відхиляється з поясненням. Кожна дія
  повертає вердикт **Перевірка: екран змінився** або **не змінився** — це
  порівняння знімків до і після, а не просто факт, що знімок вдався.

Діагностика пише в консоль головного процесу рядки з префіксом `[ComputerUse]`:
`Tool Selected`, `Window Focused`, `Screenshot Captured`, `Element Found`,
`Mouse Action Executed`, `Keyboard Action Executed`, `Verification Passed`,
`Verification Failed`.


## Безпека

- **Пісочниця шляхів.** Кожен шлях від моделі проходить через `Workspace.safe()`,
  який доводить, що результат лежить усередині папки проєкту. `../../Windows/...`
  і абсолютні шляхи на інші диски відхиляються.
- **Сервер прев'ю** слухає лише на `127.0.0.1` на випадковому порту й так само
  не віддає нічого за межами папки проєкту, включно із закодованим traversal.
- **Рендерер ізольований**: `contextIsolation: true`, `nodeIntegration: false`,
  жорсткий CSP, а доступ до Node — лише через перелічені поіменно методи в
  `preload.ts`, без універсального `invoke(channel, …)`.

## Моделі

Список тягнеться живим із `/v1/models?available=true`. Моделі без підтримки
tools не показуються — агентний цикл ними керувати не може.

Вибір моделі — **унизу біля поля вводу**, а не у верхній панелі. Список
відсортовано від найновіших і найсильніших сімейств до старих маленьких:
Opus/Sonnet, GPT-5/o-серія, Gemini 3, Grok 4, DeepSeek R1, потім менші
локальні моделі. `auto` стоїть першим як роутер, що обирає живу модель на кожен
запит. Біля кожної моделі видно її ліміт контексту з каталогу провайдера.

Кільце біля поля вводу показує, скільки контексту вже зайнято, а клік по ньому
розкладає цифру на системний промт, опис інструментів і повідомлення. Це
оцінка за символами (латиниця ~4 символи на токен, кирилиця ~2,2), а не
токенайзер конкретної моделі.

**Якщо контекст не вміщається в ліміт вибраної моделі**, Vela перед ходом
перемикається на найсхожу модель із достатнім вікном: спершу того самого
сімейства (Claude → Claude), далі — найближчу за рівнем. У чаті з'являється
рядок, чому саме відбулося перемикання. Якщо модель падає вже під час
відповіді, фолбек іде тим самим живим списком, а не жорстко прописаним
ланцюжком; він спрацьовує лише доки в інтерфейс ще нічого не надруковано, щоб
не склеїти дві різні відповіді.

## Перевірка

```bash
npm run typecheck
```

```bash
set VELA_API_KEY=freellmapi-... && npm run smoke
```

`smoke` ганяє ядро без Electron проти справжнього шлюзу: пісочниця шляхів,
доступність шлюзу, повний агентний цикл на реальній задачі, збереження прогресу
під час ходу, блокування запису після відмови в дозволі, і наскрізну перевірку
вкладеного зображення — включно з автоматичним перемиканням на модель із зором.

```bash
npm run test:store
```

`test:store` перевіряє сховище без Electron: міграцію старого формату, те що
чати проєкту не протікають у звичайні, видалення, закріплення й те, що
пошкоджений файл не затирається.

## Іконка та збірка .exe

```bash
npm run icon
```

Рендерить `assets/icon.svg` силами самого Electron, без графічних бібліотек:
`assets/icon.png` рівно 256×256 і `assets/icon.ico` з розмірами 256/64/48/32/16.
Скрипт сам перевіряє, що кути прозорі — інакше заокруглення не видно й іконка
виглядає квадратом.

```bash
npm run dist
```

Збирає `release/win-unpacked/Vela.exe`. **Закріплювати на панелі завдань і
класти ярлик на робочий стіл треба саме його**: при запуску через `npm start` Windows бачить `electron.exe` і
показує стокову іконку Electron — це не баг застосунку, а наслідок запуску в
режимі розробки.

Два обхідні кроки всередині скрипта (обидва через особливості цієї машини):

- electron-builder завантажує Electron, але архів розпаковується без
  `electron.exe`, тому `electronDist` указує на повний дистрибутив у
  `node_modules`;
- його ж бандл `winCodeSign` (у якому лежить rcedit, що вшиває іконку) містить
  macOS-симлінки, а їх створення потребує Developer Mode. Скрипт дістає з
  архіву лише rcedit і сам ставить іконку та version-рядки. Тому ненульовий код
  виходу пакувальника не вважається провалом — вирішує наявність exe.

## Структура

```
src/main/        головний процес
  gateway.ts     клієнт FreeLLMAPI: каталог моделей, SSE-стрімінг, фолбек
  agent.ts       агентний цикл: стрім → інструменти → результати → далі
  store.ts       проєкти, чати та їхні історії
  skills.ts      реєстр скілів (.md з frontmatter)
  mcp.ts         клієнт протоколу MCP (stdio та http)
  connectors.ts  реєстр конекторів: конфіг, сесії, диспетчеризація викликів
  fsx.ts         запис файлів із відкотом, коли rename недоступний
  tools/index.ts інструменти файлів, пошуку, шелу й скілів
  workspace.ts   пісочниця шляхів
  preview.ts     локальний сервер прев'ю
src/preload/     місток до Node через contextBridge
src/shared/
  model-rank.ts  рейтинг моделей і вибір найсхожої при ліміті
  tokens.ts      оцінка токенів для індикатора контексту
src/renderer/
  renderer.ts    інтерфейс
  highlight.ts   підсвітка синтаксису
scripts/
  smoke.ts       e2e-перевірка ядра
  make-icon.cjs  рендер іконки
```

## Відомі обмеження

- `npm audit` показує попередження у транзитивних залежностях
  `electron-builder`. Вони лише для збірки й у рантайм не потрапляють.
- Дерево файлів показує до 4 рівнів вкладеності й оновлюється після ходу агента
  або кнопкою — файлової системи воно не слухає.
- Перейменування проєкту й підтвердження видалення — через системні
  `prompt`/`confirm`.
- Лайки/дизлайки під відповідями зберігаються лише локально: назовні нічого не
  надсилається.
- Черга повідомлень живе в пам'яті рендерера: перезапуск застосунку її очищає,
  хоча історія чатів зберігається.
- Автопошук переміщеної папки орієнтується на схожу назву та типові теки. Якщо
  папку перейменували зовсім інакше, її треба вказати вручну.
- Одночасно виконується один хід: поки агент працює, перемикання проєкту,
  створення чату й зміна робочої папки чекають завершення або зупинки.
- Рейтинг моделей і підрахунок контексту — евристики: каталог провайдера не дає
  рівня інтелекту, а точний токенайзер у застосунок не вбудований. Для вибору
  моделі й переходу на більше вікно цього достатньо, для бухгалтерії — ні.
